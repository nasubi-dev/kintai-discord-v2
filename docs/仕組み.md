# 仕組み

kintai-discord が裏で何をしているかのざっくりした説明です。使うだけなら読まなくて大丈夫です。

```
Discord ──スラッシュコマンド──▶ Cloudflare Workers ──Google Sheets API──▶ 各サーバーのスプレッドシート
                                      │
                                      ├── Cloudflare KV（サーバー設定・暗号化した認証情報）
                                      └── Analytics Engine（コマンドの利用記録）
```

## Discord から Workers へ

コマンドを打つと、Discord から Cloudflare Workers（Hono）にリクエストが届きます。Workers は署名を見て本当に Discord から来たものか確かめ、まず「処理中...」とだけ返します。スプレッドシートへの書き込みはそのあとです。こうしておくと、通信が遅くてもコマンドがタイムアウトしにくくなります。

## Google との連携（`/init`）

Google Cloud のプロジェクトと OAuth クライアントは、サーバーごとに管理者が自分で作ります。管理者が `/init` から Google の認証をすると、受け取った OAuth トークンを AES-GCM で暗号化して、スプレッドシートの ID と一緒に KV に保存します。

勤怠データそのものは、そのサーバーの管理者の Google アカウントにあるスプレッドシートにだけ書き込みます。

## 打刻（`/start` と `/end`）

- `/start`: スプレッドシートに 1 行足します
- `/end`: スプレッドシートからその人の終わっていない行を探し、終了時刻とやったことを書いて、勤務時間を計算します

勤務中かどうかもスプレッドシートを見て判断するので、二重の `/start` や、開始していない `/end` はそこで止めます。Google Sheets API の呼び出しが失敗したときは、最大 3 回までやり直します。

## 利用記録

コマンドを処理するたびに、コマンド名、成否、処理時間、サーバー ID、匿名化したユーザー識別子を Cloudflare Workers Analytics Engine に 1 件書きます。利用状況の集計に使っていて、3 か月で自動で消えます。

ユーザー識別子は、Discord のユーザー ID と日付（日本時間）を秘密鍵で HMAC-SHA256 にかけた値の先頭 16 桁です。同じ日の同じ人は同じ値になるので、1 日に何人使ったかは数えられます。日が変わると値も変わり、秘密鍵は Cloudflare の secret にしか置いていないので、値から元のユーザー ID はたどれません。

## 使っている技術

TypeScript、Hono、Cloudflare Workers、Cloudflare KV、Cloudflare Workers Analytics Engine、Google Sheets API、Bun
